/security-review 命令

概述

Claude Code 内置了 /security-review 命令，提供与 GitHub Action 相同的安全分析功能，但直接集成到您的 Claude Code 开发环境中。

要使用此功能，只需在 Claude Code 中运行 /security-review 即可对所有待更改进行全面的安全审查。

命令配置文件

命令配置文件位于：.claude/commands/security-review.md

配置内容

点击"加载命令配置"按钮查看完整内容

自定义命令

默认的 /security-review 命令设计适用于大多数情况，但您也可以根据特定安全需求进行自定义：

  1. 将 .claude/commands/security-review.md 文件从本仓库复制到您项目的 .claude/commands/ 文件夹中
  2. 编辑 security-review.md 来定制安全分析，例如添加组织特定的误报过滤说明

自定义过滤说明

概述

Claude Code Security Reviewer 支持自定义误报过滤说明，允许您根据特定环境和需求调整安全分析。

使用方法

  1. 创建包含自定义过滤说明的文本文件（例如 .github/false-positive-filtering.txt）
  2. 在工作流程中引用它： 
    name: Security Review

permissions:
  pull-requests: write
  contents: read

on:
  pull_request:

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha || github.sha }}
          fetch-depth: 2

      - uses: anthropics/claude-code-security-review@main
        with:
          comment-pr: true
          claude-api-key: ${{ secrets.CLAUDE_API_KEY }}
          false-positive-filtering-instructions: .github/false-positive-filtering.txt

文件格式

文件应包含纯文本，分为三个主要部分：

  • HARD EXCLUSIONS：列出应自动从发现中排除的模式
  • SIGNAL QUALITY CRITERIA：评估发现是否代表真实漏洞的问题
  • PRECEDENTS：针对您环境中常见安全模式的具体指导

最佳实践

                    
    
                        
  1. 从默认开始：先使用默认说明，然后根据遇到的误报进行修改
    2. 
                        
  2. 具体说明：包括有关安全架构的详细信息（例如，"我们使用 AWS Cognito 进行所有身份验证"）
    3. 
                        
  3. 记录假设：解释为什么排除某些模式（例如，"k8s 资源限制可防止 DOS"）
    4. 
                        
  4. 版本控制：与代码一起跟踪过滤说明的变更
    5. 
                        
  5. 团队审查：让您的安全团队审查并批准过滤说明
    6. 
                    

                

            

        


        
        

            

                
自定义安全扫描说明

                

                    
概述

                    
Claude Code Security Reviewer 支持自定义安全扫描说明，允许您向安全审计添加组织特定的漏洞类别。

                    
默认安全扫描涵盖常见的漏洞类别，如 SQL 注入、XSS、身份验证问题等。但组织通常有基于以下方面的特定安全问题：

                    
    
                        
  • 技术栈（GraphQL、gRPC、特定云提供商）
    • 
                        
  • 合规要求（GDPR、HIPAA、PCI DSS）
    • 
                        
  • 行业特定漏洞（金融服务、医疗保健）
    • 
                        
  • 自定义框架和库
    • 
                    

                


                

                    
使用方法

                    
    
                        
  1. 创建包含自定义安全类别的文本文件（例如 .github/custom-security-categories.txt）
    2. 
                        
  2. 在工作流程中引用它：
                            
    name: Security Review

permissions:
  pull-requests: write
  contents: read

on:
  pull_request:

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha || github.sha }}
          fetch-depth: 2

      - uses: anthropics/claude-code-security-review@main
        with:
          comment-pr: true
          claude-api-key: ${{ secrets.CLAUDE_API_KEY }}
          custom-security-scan-instructions: .github/custom-security-categories.txt

    
                        
    3. 
                    

                


                

                    
文件格式

                    
文件应包含与默认类别相同格式的附加安全类别。每个类别应：

                    
    
                        
  • 以粗体的描述性标题开头（使用 **Category Name:**）
    • 
                        
  • 列出要检查的特定漏洞或模式
    • 
                        
  • 使用清晰、可操作的描述
    • 
                    

                    
示例结构：

                    
**Category Name:**
- Specific vulnerability or pattern to check
- Another specific issue to look for
- Detailed description of what constitutes this vulnerability

**Another Category:**
- More specific checks
- Additional patterns to identify


                


                

                    
示例

                    

                        

                        
                    

                


                

                    
工作原理

                    
您的自定义说明会附加到默认"数据暴露"类别之后的安全审计提示中。这意味着：

                    
    
                        
  1. 所有默认类别仍会被检查
    2. 
                        
  2. 您的自定义类别会扩展（而非替换）默认扫描
    3. 
                        
  3. 相同的 HIGH/MEDIUM/LOW 严重程度准则适用
    4. 
                    

                


                

                    
最佳实践

                    
    
                        
  1. 具体说明：提供关于每个漏洞构成的清晰描述
    2. 
                        
  2. 包含上下文：解释为什么某些问题在您的环境中是漏洞（例如，"我们的支付处理系统要求加密"）
    3. 
                        
  3. 提供示例：尽可能描述特定的攻击场景
    4. 
                        
  4. 避免重复：检查默认类别以避免冗余
    5. 
                        
  5. 保持专注：只添加与您的代码库相关的类别
    6. 
                    

                


                

                    
默认类别参考

                    
默认扫描已包括：

                    
    
                        
  • 输入验证：SQL 注入、命令注入、XXE 等
    • 
                        
  • 身份验证与授权：身份验证绕过、权限提升、会话管理等
    • 
                        
  • 加密与密钥管理：硬编码密钥、弱加密算法、不当密钥管理等
    • 
                        
  • 注入与代码执行：远程代码执行、反序列化攻击等
    • 
                        
  • 数据暴露：敏感数据泄露、PII 处理违规等
    • 
                    

                    
您的自定义类别应补充这些内容，而不是重复它们。

                

            

        


        
        

            

                
使用指导和示例


                

                    
快速开始

                    
将以下内容添加到您仓库的 .github/workflows/security.yml 中：

                    
name: Security Review

permissions:
  pull-requests: write  # Needed for leaving PR comments
  contents: read

on:
  pull_request:

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha || github.sha }}
          fetch-depth: 2

      - uses: anthropics/claude-code-security-review@main
        with:
          comment-pr: true
          claude-api-key: ${{ secrets.CLAUDE_API_KEY }}

支持的漏洞类型

                    
    
                        
  • 注入攻击：SQL 注入、命令注入、LDAP 注入、XPath 注入、NoSQL 注入、XXE
    • 
                        
  • 身份验证与授权：身份验证绕过、权限提升、不安全的直接对象引用、绕过逻辑、会话缺陷
    • 
                        
  • 数据暴露：硬编码机密、敏感数据记录、信息泄露、PII 处理违规
    • 
                        
  • 加密问题：弱算法、不当密钥管理、不安全的随机数生成
    • 
                        
  • 输入验证：缺失验证、不当清理、缓冲区溢出
    • 
                        
  • 业务逻辑缺陷：竞争条件、检查时间/使用时间（TOCTOU）问题
    • 
                        
  • 配置安全：不安全的默认值、缺失的安全头、宽松的 CORS 策略
    • 
                        
  • 供应链：易受攻击的依赖项、拼写错误的包名风险
    • 
                        
  • 代码执行：通过反序列化的 RCE、pickle 注入、eval 注入
    • 
                        
  • 跨站点脚本（XSS）：反射型、存储型和 DOM 型 XSS
    • 
                    

                


                

                    
误报过滤

                    
该工具会自动排除各种低影响和容易误报的发现，以专注于高影响的漏洞：

                    
    
                        
  • 拒绝服务（DOS）漏洞
    • 
                        
  • 速率限制问题
    • 
                        
  • 内存/CPU 耗尽问题
    • 
                        
  • 没有已证实影响的通用输入验证
    • 
                        
  • 开放重定向漏洞
    • 
                    

                    
误报过滤也可以根据特定项目的安全目标进行调整。
